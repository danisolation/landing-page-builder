# Taste — Frontend (Next.js)

- Prefers TanStack Query for all API data fetching, caching, and refetch/invalidation. Confidence: 0.9
- Dislikes overly long files — wants components split into small, focused files following current common FE structure. Confidence: 0.85
- Cares about visual polish of both internal (admin) and public UI; judges results visually and reports layout issues such as misalignment. Confidence: 0.8
- Vietnamese is the default locale; the Vietnamese UI must contain no leftover English strings — all user-facing text goes through i18n. Confidence: 0.8
- For FE work the agent may implement directly, but must explain the changes afterwards. Confidence: 0.7
- Previews (full-page and per-section) should show complete content without internal scrolling, adapt to each screen size ("phù hợp với từng màn hình"), and be centered at normal width — the per-section preview should mirror the full-page preview experience. Confidence: 0.7
- Values a visual/WYSIWYG editing experience — live canvas with click-to-edit, drag-drop section reordering, inline text editing, and real-time preview are core features, not nice-to-haves. Confidence: 0.8
- Prefers simple, conventional UI design meant for ordinary users — dislikes "bizarre" or overly complex interfaces; when the user called the editor "bizarre and the UX is terrible," the agent acknowledged it was overengineered and offered to simplify. Confidence: 0.85
- Layouts must be analyzed for feasibility before implementation — text overflow, clipping, and cutoff issues should be caught during design, not reported by the user after the fact; the user expects the agent to think through how layouts actually work visually, and rebukes the agent harshly when broken layout slips through ("Your standards are so low"). Confidence: 0.85
- Responsive design must be logical and never break the layout at any width (e.g. 1 card per column on mobile, no squeezed or broken text). Section components render inside narrowed containers (editor mobile/tablet preview, preview modal) where viewport breakpoints (`sm:`/`md:`) never trigger; use Tailwind v4 container queries (`@container` + `@2xl:`/`@3xl:`) so layout reacts to the actual container width in every context. Confidence: 0.9
- Prefers standardized, cohesive section layouts with consistent spacing/typography tokens for a professional look; existing visual effects should be preserved while standardizing layout. Confidence: 0.8
- Verify features are actually wired, not merely present: InlineTextEditor was fully written but imported by no section (isEditing/onContentChange props accepted and ignored), so the core click-to-edit promise didn't exist — every section component must render InlineTextEditor through its isEditing/onContentChange props. Confidence: 0.85
- In the editing canvas, interactive elements are inert content: in-content anchors must preventDefault (href="#" jumps to page top, real links would navigate the editor away) while public/preview pages keep normal navigation; destructive actions like section delete get a confirm dialog consistent with the page-delete flow. Confidence: 0.75
- Interactive/editing affordances must default to read-only and be opted in per context: InlineTextEditor's `editing` prop defaults to false, so the preview modal and public pages render plain inert tags (no "Click to edit" tooltip, no input appears on click); only the editor canvas (EditableSection) passes isEditing={true}. When wiring interactive behavior into a shared component, verify every render context separately (editor canvas, preview modal, public page). User explicitly: click-to-edit in preview "is not permitted." Confidence: 0.85
- Derived form fields must auto-fill for no-code users: the slug auto-generates from the title with Vietnamese diacritics stripped (NFD normalize, đ→d) plus a live URL preview, and auto-fill stops once the user manually edits the slug. Confidence: 0.8
- next/font CSS variables must be set on <html> (where the font-sans token is applied), not on <body> — body-level variables left the html font-sans chain unresolvable and the entire app silently fell back to Times serif. Confidence: 0.9
- Avoid custom utility classes that tailwind-merge cannot classify: a custom .text-wrap-balance was treated as a text-color class and silently swallowed preceding classes like text-white — use Tailwind v4's built-in text-balance instead of custom text-* utilities. Confidence: 0.85
- React 19 never executes `<script>` tags rendered inside React components (hydration console error "Encountered a script tag while rendering"), and `next/script strategy="beforeInteractive"` is not viable in this app's architecture where `<html>` lives in `[locale]/layout.tsx` — tried before `<body>`, inside `<body>`, and in a pass-through root layout; all dead ends. For JS-gating (e.g. scroll-reveal no-JS fallback), drop inline scripts entirely and use native CSS `@media (scripting: none)` to force content visible — warning-free, no hydration risk, verified clean in a real browser. Confidence: 0.8
- CounterAnimation (stats sections) counts integers only (`Math.floor`): stat values must be integers with the unit/decimal part expressed via a suffix field (`15` + `"K+"` → "15K+", `24` + `"/7"` → "24/7"); string values like "99.9%" or "4.9★" are unrepresentable and render as "0+". Confidence: 0.8
